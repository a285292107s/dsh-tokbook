# 代码注释规范 — dsh-tokbook

> **Doc meta** · role: reference · language: zh-CN · status: current · last-reviewed: 2026-09-18 · supersedes: —

本仓库注释的唯一读者是 AI（单人维护 + AI 辅助）。判据因此不是「写得清不清楚」，而是
**这条信息 AI 从代码里读不读得出来**——读得出来的不写。全文只一条尺子、四类该写、四类不写。

## 一条尺子

**只写「代码里读不出来、且改了代码必须同步改它」的东西。**

| 该写 | 本仓库的例子 |
|---|---|
| **外部世界的事实**（DSH 契约、第三方 API 行为） | `quota-official.ts`：401 是坏 key、403 是有效 key 无订阅；Cloudflare 会挡掉非浏览器 UA。`sync.ts`：`listSnapshots()` 才有变更令牌，裸 `list()` 没有 |
| **不变量与陷阱**（违反后不报错，只是悄悄错） | `client/index.ts` 不能有 `default` 导出；`client/styles.ts` 那行不能用模板字符串；`styles/tokens.ts` 的自有 token 必须挂在插件根上 |
| **非直觉取舍的一句 why** | 读路径为什么绝不 await 后台 walk；现金与订阅两个金额桶为什么不靠颜色分 |
| **跨文件的耦合**（A 改了必须改 B） | 骨架块高度 = 真块高度；趋势图的轴行与图区必须同一个内边距 |

## 四不写

1. **改动史。** 「此前 / 上一版 / 曾试过三版 / D-0xx 撤掉」不写——git 是流水账的去处，
   仍然生效的取舍写进 `docs/DECISIONS.md` 一条，代码里不复述。
2. **代码已经说了的。** 类型名、CSS 值、一眼能看出的结构、以及 `@module` 这类路径复述。
   `/** 四桶之和。 */` 这种字段复述只在它给出代码里没有的**口径**时才留（如「未知 ≠ 0」）。
3. **会被下一次调参推翻的数值推导。** 逐项预算加总、实测 px 明细、「这几个数怎么来的」都不写：
   值就在代码里。要留就留**约束**——「这个值由首屏预算导出，改它之前先重量」。
4. **同一条规则的第二份副本。** 规则只在真源处写一遍，别处引用，不复述整句理由。真源：
   配色 / 字号 / 对比度 → `styles/tokens.ts` + `docs/UI-SPEC.md`；口径与不变量 → `docs/CONTRACTS.md`；
   取舍理由 → `docs/DECISIONS.md`；界面机制 → `styles/shared.ts` 与各片段。

## 形态

- **一句话优先。** 一段注释超过 ~8 行，或要分「①②③」讲历史，基本就是该删的信号。
- **文件头**只写「这个文件在系统里的位置 + 读不出来的前提」。样式分片的拼接顺序是例外——
  它是契约，写在 `client/styles.ts`（**唯一一处**），片段自己不再重复「由 injectStyles 拼接」。
- **解释名字的注释 = 改名信号。** 需要注释说明某个参数/字段是什么意思，先改名字
  （`formatHitRate` 因名不副实被改成 `formatRatio`，注释随之删掉）。
- **具体数字、标识符、文件名出现在注释里时，改代码要顺手核对它。** 本次全库审核抓到的两条
  过期注释都是这么来的：一处说「卡的下沿是刻度轨」（轨早撤了），一处说列头照数据的**两行**写
  （正文与它下面两行注释都说是一行）。
- **注释与代码冲突时以代码为准**，当场改注释；无法判断哪边对时，把问题写进 `LESSONS.md` 或
  直接删掉这句话，不要留一句存疑的断言。
- 中文。**强调**与「」的用法沿用既有风格；标识符、命令、字段名保留英文原样。

## 落笔前的三问

1. 删掉它，AI 只看代码会不会做错事？**不会 → 删。**
2. 这段代码明天改一个值，这条注释要不要跟着改？**要 → 它在替代码记事**：删掉，或压成一句约束。
3. 这条规则在别处写过一遍了吗？**写过 → 删这里**，或改成一句引用。
