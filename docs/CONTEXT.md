# 领域词汇 — dsh-tokbook

本文件只收**新引入、且会被反复用错**的词。既有词汇**不在这里重复**，它们各有单一真源：

- 通道 / 模型厂商 / 未归属 → [`CONTRACTS.md`](CONTRACTS.md) §1
- 未上报用量 / 价格未知 / 实际支出 / 订阅价值 / 计费性质 → [`CONTRACTS.md`](CONTRACTS.md) §2

## 会话词元页（对话视图环的第三个 tab，标签「词元」）

- **轮次（turn）** —— 宿主分配给一轮的编号，取自会话事件载荷的 `turn`（`turn/start`、`assistant/message` 都带）。
  **原样显示，不做加减**：轨迹 tab 也是把载荷值直接渲染成「第 N 轮」（`sectionLabel` = `第 {turn} 轮`）。
  两页的轮次号必须是同一个数，否则用户在两页之间对不上号。
- **步骤（step）** —— 一轮里的一次模型调用，加上它请求的工具执行（`step/start` 的定义原文：一次模型调用加它请求的工具执行）。
  账本里**一步就是一行**计费调用，所以「步骤明细」不用另立结构，就是账本行本身。
- **轮间（between turns）** —— **确定地**不属于任何轮次的计费调用。目前只有压缩 summarize：
  `compaction/summary` 不带 `turn`（`turn` 只出现在 `compaction/start` / `compaction/end` 上，且可为 `null`）。
  轨迹 tab 用的是同一个词（`section.betweenTurns`）。压缩因此**不硬塞进某一轮**，单列一块。
- **轮次未知** —— 账本行**没能拿到**轮次/步骤。与「轮间」不是一回事：
  轮间是**知道**它不属于任何轮次，轮次未知是**不知道**。两者必须分开显示，不能合并成「其他」。

## 这一页的呈现口径（都不是账本字段，是读法）

- **新增词元** —— 图表上格那根柱的**柱高**编码的量：**未缓存输入 + 缓存写 + 输出**。
  它与**缓存读**互补：缓存读是**复用**的上下文，新增词元是本轮**新产生**的部分（含写进缓存的那部分输入）。
  两者之和才是四桶总量。**柱子的标题必须写明另一格那个数**——实测里缓存读能占四桶的 99%，
  不写清就会被当成总量读。
- **一格一把尺子** —— 每轮是**两格**小图：上格新增词元、下格缓存读取，各格按自己的最大值归一，
  **柱高不可跨格比较**。不画成「一列里并排两根柱」：两把尺子并排时读者会比高度，而两者的量级差着几十倍；
  两格的合计与峰值都写在格头上，量级差多少由那两个数说。
- **轮次未知与轮间分列** —— 两者不能合并成「其他」：轮间是**知道**不属于任何轮次（压缩 summarize），
  轮次未知是**不知道**（见上）。界面上它们是两块，不是一块。
- **非对话视图的渲染契约** —— 这一页的根带 `data-conversation-composer-overlay`，自己撑满视图区、
  自己滚动、底部留出输入框的高度（`--dsh-composer-height`）。宿主的 `:has()` 只认这个属性：带了它
  输入框才是**飘在视图上**的，不带就是 `sticky` 压在内容上——视口最后 128px 归输入框，我们的内容
  在那儿读不到也点不到，而且滚不出来。轨迹 tab 走的是同一套。
- **列宽是这一页自己的** —— 默认跟着对话正文那条列（`--dsh-chat-content-width`），两侧留白里各有一枚
  手柄可拖（宿主那对手柄在非对话视图下被它自己的 CSS 藏了），拖 / 方向键改的是这一页存下的宽度
  （`localStorage` 的 `dsh-tokbook.tokens.contentWidth`），双击回到跟随。**对话那一页不受影响**。

## 与其他面的关系（避免两个入口互相打架）

- 浮窗的**用量总览 / 用量明细**是**跨会话 · 按窗口**的视角；**词元**这一页是**单会话 · 全生命周期**的视角；
  **项目行入口**给出的是**单项目 · 按窗口**的视角（点开仍落到用量明细那一页，只是清单筛到一个项目）。
- DSH 自己的会话级读数各有归属，本页**不重复**它们：整会话轮次数/步骤数/墙钟时间由 `sessionStats` 投影提供，
  四桶 token 由 `tokenUsage` 投影提供，上下文构成（system / tools / messages 的**估算**）由 `contextBreakdown` 投影提供并由 composer 的 ContextMeter 显示。
  本页的 token 与钱**只取账本**——同一批数字不设第二个来源（理由见 [`adr/0001-turn-attribution-read-time-join.md`](adr/0001-turn-attribution-read-time-join.md)）。

## 侧栏项目行入口

- **项目行（project row）** —— 侧栏按工作区分组时代表**一个已注册工作区**的那条分组行（折叠箭头 + 名称 + ⋯ + ⊕）。
  它**不是**一条会话行：会话行有宿主声明的扩展位，项目行没有（见
  [`adr/0002-project-row-entry-via-dom-injection.md`](adr/0002-project-row-entry-via-dom-injection.md)）。
- **项目身份** —— 项目行的身份就是工作区注册表的 `workspaceId`；它与账本侧 `WorkspaceUsageRow.id`
  **是同一个值**，所以「这行是哪个项目」不用另开一条数据通路。**未归属**分组没有这个身份
  （见 [`CONTRACTS.md`](CONTRACTS.md) §1），因此也没有这枚入口。
- **注入点（injection point）** —— 这枚入口图标在宿主 DOM 里落地的坐标：项目行行尾那个操作容器里、
  ⋯ 之前。它**不是 slot**，是本插件唯一一处直接操作宿主 DOM 的地方。
