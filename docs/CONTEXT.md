## 会话词元页（对话视图环的第三个 tab，标签「词元」）

- **轮次（turn）** —— 宿主分配给一轮的编号，取自会话事件载荷的 `turn`（`turn/start`、`assistant/message` 都带）。
  **原样显示，不做加减**：轨迹 tab 也是把载荷值直接渲染成「第 N 轮」（`sectionLabel` = `第 {turn} 轮`）。
  两页的轮次号必须是同一个数，否则用户在两页之间对不上号。
- **步骤（step）** —— 一轮里的一次模型调用，加上它请求的工具执行（`step/start` 的定义原文：一次模型调用加它请求的工具执行）。
  账本里**一步就是一行**计费调用，所以「步骤明细」不用另立结构，就是账本行本身。
- **轮间（between turns）** —— **确定地**不属于任何轮次的计费调用。目前只有压缩 summarize：
  `compaction/summary` 不带 `turn`（`turn` 只出现在 `compaction/start` / `compaction/end` 上，且可为 `null`）。
  轨迹 tab 用的是同一个词（`section.betweenTurns`）。压缩因此**不硬塞进某一轮**，单列一块。
- **轮次未知** —— 账本行**没能拿到**轮次/步骤。与「轮间」不是一回事：
  轮间是**知道**它不属于任何轮次，轮次未知是**不知道**。两者必须分开显示，不能合并成「其他」。
- **子代理（subagent）** —— 本会话**直接**派出的下级会话（宿主 header 的 `origin === 'subagent'`）。
  它的用量记在自己的 `sessionId` 下，词元页按会话血缘折成「子代理」一段。一个直接子代理那一行
  包含它**自己派出的下级**（整棵子树）；嵌套后代不各自占行，否则子树成本会被重复加。
  **用户手动 fork 的会话有 `parentSession` 但 `origin` 缺席，不算子代理**。抬头合计不并入子代理。

## 这一页的呈现口径（都不是账本字段，是读法）

- **新增词元** —— 图表上格那根柱的**柱高**编码的量：**未缓存输入 + 缓存写 + 输出**。
  它与**缓存读**互补：缓存读是**复用**的上下文，新增词元是本轮**新产生**的部分（含写进缓存的那部分输入）。
  两者之和才是四桶总量。**柱子的标题必须写明另一格那个数**——实测里缓存读能占四桶的 99%，
  不写清就会被当成总量读。
- **一格一把尺子** —— 每轮是**两格**小图：上格新增词元、下格缓存读取，各格按自己的最大值归一，
  **柱高不可跨格比较**。不画成「一列里并排两根柱」：两把尺子并排时读者会比高度，而两者的量级差着几十倍；
  两格的合计与峰值都写在格头上，量级差多少由那两个数说。
- **轮次未知与轮间分列** —— 两者不能合并成「其他」：轮间是**知道**不属于任何轮次（压缩 summarize），
  轮次未知是**不知道**（见上）。界面上它们是两块，不是一块。
- **非对话视图的渲染契约** —— 这一页的根带 `data-conversation-composer-overlay`，自己撑满视图区、
  自己滚动、底部留出输入框的高度（`--dsh-composer-height`）。宿主的 `:has()` 只认这个属性：带了它
  输入框才是**飘在视图上**的，不带就是 `sticky` 压在内容上——视口最后 128px 归输入框，我们的内容
  在那儿读不到也点不到，而且滚不出来。轨迹 tab 走的是同一套。
- **列宽是这一页自己的** —— 默认跟着对话正文那条列（`--dsh-chat-content-width`），两侧留白里各有一枚
  手柄可拖（宿主那对手柄在非对话视图下被它自己的 CSS 藏了），拖 / 方向键改的是这一页存下的宽度
  （`localStorage` 的 `dsh-tokbook.tokens.contentWidth`），双击回到跟随。**对话那一页不受影响**。

## 用时（这一页的时间读数）

- **引擎工作总时长** —— 该会话**各步的模型用时 + 工具用时**之和。它**不含**等待：等用户输入、
  等外部任务、会话被挂起，都不算「在算」。块头的「用时」与整页的「引擎工作」是**同一条加法**
  （`settleTiming`），不是两个各算一套的读数。
- **会话跨度** —— 该会话**日志首末事件之差**，含挂起。它必须与「引擎工作」**并排**出现：单看哪个都
  不说明问题，差额（没在算的时间）才是这两个数存在的理由。
- **未计时** —— 这一步**量不到**任何起止事件（或只有墙钟、没有产出段）。**不是 0**：
  0 是「花了 0 秒」，未计时是「不知道」。同「用量未知 ≠ 0」（[`CONTRACTS.md`](CONTRACTS.md) §2）。
- **无产出** —— 这一步行了墙钟但没有 `assistant/message`（取消 / 重试耗尽）。那段时间耗在重试与
  退避上，**不归属到「模型用时」**——报成模型用时是假话。
- **首 token（TTFT）与生成** —— 一步里从 `step/start` 到**第一个真正产出的 token**、以及从它到收尾
  的两段；「模型用时」正是这两段之和。取法沿用宿主 `dsh-llm` 的规则（打包段累加 `dt`，块的起止不算
  token），否则会把「块开始」当首 token。
- **输出速度（TPS）** —— 输出词元 ÷ 生成时长。它**只**出现在步骤行上：整会话的平均速度是宿主统计
  浮窗的事，搬到这里会把这一页自己的分辨率抹掉。
- **构成尺** —— 把用时按组成摊成一条线，答的是「**形状**」：哪一步几乎全在等工具；精确的数仍是它
  旁边那张表。**块头那条尺下面同一串读数把它报成数字**（记号 + 段名 + 值，与步骤表同取一份
  `PHASE_LABEL`）：收起的一轮也答得出「等首 token 等了多少、工具花了多少」，不必展开逐步相加；
  形状归尺，绝对值归这串数。**步骤行与块头是同一条尺的两个尺度**：三段、按真实先后排（等首 token → 生成 →
   工具），块头那条就是它下面各步那几条的**和**（逐像素可核）；**抬头**那条是另一族
  （「引擎工作 + 没在算的时间」，两段等高），而且**两段各自带名字与数**——它大半是浅灰、又不带
  刻度，不写名字就只能读成进度条（「进行到几成」），而这两段都是终值。
  为什么步骤行要拆出「等首 token」：它是模型那格里最容易被误读的一半——实测首 token 占模型用时
  的一半以上，也就是「模型用时 4.9 秒」里有两秒多不是在生成，而是在等上游。只画「模型 + 工具」
  两段会把这段等待藏进「模型」，恰是这一页最该说清的事。
  **只有块头那条尺有长度**（按「整节最重的那一轮」这个唯一分母缩放，并且**画一条轨道**：没有轨道，
  一段 145ms 与一段 5 分钟都只是一小截灰，「只占这么一点」这句话就没地方待）。**步骤尺铺满整行、没有
  长度通道**——它答的是「这一步花在哪三段」，量级归右边那张等宽表（一列一个量，竖着扫就是趋势）。
  两条尺的段边界同源（块头的段边界是各步段边界的加权平均），所以同一轮在收起与展开下是同一个形状。
  分不出组成的步（重试耗尽，只有整段墙钟）**不进尺**；拆不开的模型段（通道不上报流，量不到首
  token）画成整段、不与「生成」混同——「生成」断言了「没有等待」，而这里是「不知道有没有等待」。
  **相位走明度与断开、走纹样、不走色相**：三档明度、段间 1px 断开——相邻两段即使明度接近，
  也先是两个各自完整的矩形。这是条**很窄的窗口**：最浅那档不能再往下压（再浅就掉出 3:1，成了一条
  看不见的轨道），最深那档贴着满墨，所以能拉开的只有中间那段。**不要**用高度去补明度：按高度分档
  在 16px 上读出来是「三根长短不齐的柱子」，像坏掉的控件而不像一条比例条。
  确切取值与实测对比度见下面「取值与样式口径」里构成尺那几条。
  **明度之外还有一条纹路通道**：真实步骤行里一段常常只有二三十像素宽（实测最窄 24px，而 `max(2px, …)`
  的下限允许 2px 的段存在），跨段比明度需要一个共同参照，单看一段时纹路比明度可靠。四类各一条，
  按语义挑：等首 token 竖细线、生成实心（整页唯一一块「满」，其余三类都带纹路）、工具 45° 斜纹、
  **拆不开的模型段交叉网格**（竖线 + 斜纹叠加，正是「这两类分不出来」；它也是四类里唯一两向叠加的，
  扫一眼不必比明度就能认出来）。纹路与底色是同一族的墨，所以**模型的底色必须比纹路浅**
  ——底色也压满墨时纹路合成上去仍是满墨，整段读成一块实心，与「生成」一模一样。
  图例是一条**真的示例尺**（复用同一个组件，明度与纹路逐字同源），不是三枚孤立的小方块：读者只会
  看到几个深浅不同的方块——图例就变成了教「看颜色」。
  它是**表的一部分**，不是第二套读数——所以对读屏隐藏（数字那张表才是给 AT 的版本）。

## 取值与样式口径（tokens 与样式片段）

- **`styles/tokens.ts` 是唯一的取值登记处，加一条值之前先过三问。** 别处是否已经表达过同样的色值 / 圆角 /
  名字；是不是真有两个使用处——只有一个就写在使用处的类上，别挂到根上；色值是不是必须来自宿主，是的话
  就走 `--dsw-alias-*` 加兜底，**不许把宿主解析后的具体值抄进来**。挂到根上没有使用者的就是死 token，删。
- **自定义属性必须挂在插件根上。** 它在计算值阶段解析：定义在使用者自己的类里，别处取不到，而失效是
  静默的——整条声明（比如 `grid-template-columns`）直接不生效。每个值还要同时成立于浅色与深色皮肤；
  恒定值要自己给出理由。
- **墨阶按「要不要读」分档，这是最容易用错的一处。** 要读的文本只能走 fg / fg-2；fg-3 只给装饰
  （「—」、插入符、缀点），dim 只给「·」这类行内分隔符。实测 dim 压卡面浅色 1.64:1、深色 2.50:1，
  是全表最弱的一档——拿它报一个价、一段时长或一句说明，等于没报；fg-3 压白卡 3.47:1，同样不是正文色。
  零支出是**量出来的数**，走 fg-2；只有未知才走 fg-3。
- **色相只有两处用途：品牌黄是身份，状态色是「真要看一眼」。** 分类与主次一律交给形状、字重与墨阶：
  按量与订阅是描边 vs 实心，现金与订阅价值是 600 vs 400，四档价与峰谷读数一律不染色。warn 不直接做正文
  ——它压白卡只有 2.15:1，而 11px 正文要 4.5:1；要报的字走 `--dtpl-warn-ink`（掺 45% 前景墨，实测 7.87:1），
  裸 warn 只留给边框与底色。ok 只给「已保存」，err 才是错误。
- **品牌黄恒定时压白卡只有 1.73:1，所以它只以实心块 + 墨边出现。** 它不做文字色，也不外借给数据——
  染到读数上会被读成「这一档更值得看」。它标的是「当前项」：当前 tab、峰值柱前那枚黄牌、节标题的徽记、
  草稿点、选区、价表里「此刻计费」那枚牌。金块上的字走 on-brand（压金块 5.2:1）。
- **accent 是系统信号，不是强调色。** 全局那条焦点环走它；DSH 默认皮肤里这档等于墨色，拿它做分类或
  状态是空操作，换皮肤又会变蓝。兜底取墨色而不是某个蓝——端出 DSH 里不存在的强调色更糟。
- **侧栏 footer 的焦点环必须取宿主的正文字色，不能取品牌色。** 插件拿不到「现在是不是深皮」——宿主把
  色板写成 `:root` / `body` 上的扁平值，没给选择器。深皮里品牌色近白（实测 `#f9fafb`），会在深侧栏上
  画一圈白框，读起来像按钮坏了。取正文字色是因为它本来就「压在当前皮肤背景上要读得清」：浅皮近黑、
  深皮近白，天然与脚下的面反向。两条错路别再走——照抄品牌色；想拿它与 `--dtpl-fg` 混合来中和
  （深皮里 fg 本身就是近白，混完实测仍是近白）。
- **这个按钮上不能画环，形状本身是规则。** footer 按钮平时没有自己的面，无论环画在外侧还是内侧，
  沿轮廓的一圈线都读成「被框住了」。改用本仓库已有的「当前项」语言：一档底色 + 左缘一道实心标记条。
  价格屏同理，输入框与下拉的聚焦靠「面 + 边」，不是环；只有全局那条 `:focus-visible` 还是 2px 环。
- **字号只有六档，别再写裸 px。** micro 10 / label 12 / body 14 / lead 16 / figure 20 / hero 38，
  相邻两档最小跨度 1.14 倍（micro 是例外）。旧版实测有 17 档，其中 10 / 11 / 11.5 / 12 / 13 干的是
  同一件事——彼此只差 1px 的字号读不出层级，只是让层级变得不可读。micro 只给图表轴与柱值标签
  （那些数字不承载判断），除此之外任何文字都不得小于 label。词元页那个 72px 是刻度外唯一一处：
  它是整页的主角读数，而那一页不在 720px 浮窗里；要改那一屏的层级就改它本身，别拿它当中转站。
- **有几个宽度是下限，不是定宽。** 一行读数的右列 `--dtpl-row-nums-w` 在使用处必须写成
  `minmax(min-content, …)`：金额位数不受控，写死会让右列溢出、金额被裁。词元页的读数格
  `--dtpl-tok-cell-w` 是定值：`1fr` 会把「用时」与「四桶」两簇拉到相隔几百像素，`auto` 会让
  「3.8 秒」与「10.3 秒」两行的列边界对不上，而竖着扫一列看趋势正是那张表存在的理由。图表一列的
  下限 48px 是量出来的：柱值标签最长 5 个等宽字符约 30px，峰值那根前面还有黄牌与间隔，邻柱各让一半后
  34.5px 是「刚好不叠」，而两枚数字贴在一起就读不成两个数。
- **图形承载读数时，3:1 是硬线。** 柱高、相位段、轨道、占比环、额度条都在用明度表示量，而浅色主题下
  比 45% 更淡的灰到不了 3:1（非文本对比度）。所以「这一格更淡」的层级不能靠明度做——词元页两格小图
  靠格头那句名字区分，不靠深浅。
- **构成尺的三档明度是量出来的唯一解，不是随手挑的灰。** 52 / 72 / 100 三档都要压在面板上过 3:1：
  52% 是浅色主题的下限（50% 只有 3.11，再浅就不达标），最深那档已经贴着满墨，所以能拉开的全部空间
  只有中间那一段；实测 3.29 / 6.06 / 14.63（浅色）、5.14 / 8.53 / 15.28（深色）。想「把明度拉开」
  换成 30 / 62 / 96 会让等首 token 掉到 1.87:1——它就从一档数据变成一条看不见的轨道，而这一页的口径是
  「量不到 ≠ 0」，最浅那档必须仍然看得见。
- **纹路的两档也要压过面板 3:1。** 纹路是这一段的一部分，不是缝隙：每类只在自己那档明度上再往上取一档，
  最浅那条永远不低于该类原本的底色。底色一律走 `--dtpl-fg` 的透明度，深浅两皮因此自动成立，没有一个
  写死的灰。
- **模型段的底色取 55%。** 理由见上面「用时」那条（底色也压满墨时，网格合成上去仍是满墨，整段读成
  「生成」）；55% 压面板同样过 3:1。
- **段与段之间靠 1px 内描边断开，不吃宽度。** 断开色取轨道色：带轨道的那两条里，缝读作「轨道露出来的
  一条」；步骤尺没有轨道，取同一档洗色。取 `--dtpl-panel-bg` 是错的——那是 3% 的透明色，压在段上等于
  没画，相邻两段会糊成一块（实测「生成 → 工具」就是这么糊的）。也不能改成 margin 或 border 去占宽度：
  最低 2px 的段存在，那条下限是「占比再小也看得见」的全部依据。
- **只有带长度通道的两条尺画轨道。** 轮块头与抬头那条按量级算宽度，不画轨道的话一段 145ms 与一段
  5 分钟都只是一小截灰，「它只占这么一点」就没地方待；步骤尺铺满整行、没有长度通道，几段之和就是整条
  宽度，画轨道等于给一个不存在的分母留位。轨道底取 10% 洗色（压面板约 1.6:1，一眼看得出是条凹槽），
  不能更浅——5% 压 3% 的面板只差两个百分点，实机里读成一片空白。抬头那条的浅段（没在算的时间）12%
  会掉成空白，所以取 26%；它不带纹路，因为那是「两个时长之比」，不是相位。
- **片段拼接顺序是契约。** `styles.ts` 把 tokens、hero 图、各页片段、shared、device 拼成一张表：
  tokens 在最前（其余片段全在引用它），shared 必须排在各页之后（它的窄屏与动效配方要压住各页自己的
  默认值），device 压轴（它整段只在 `[data-dtpl-device]` 根上生效，宿主里静默）。顺序打乱不会报错，
  只是某几页的窄屏或动效悄悄不再生效。
- **转场与状态回洗各有刻度，别在规则里写裸值。** 时长四档 `--dtpl-dur-quick|enter|move|draw`
  （100/200/300/450ms）、缓动两条 `--dtpl-ease-tint`（颜色、边框、背景，取宿主 `--ds-ease-in-out`）
  与 `--dtpl-ease-move`（位移、尺寸、描画）。选缓动按「动的是什么」而不是按组件：同一元素上背景的
  100ms 与高度的 300ms 各走各的。循环动画（`dtpl-spin`/`dtpl-pulse`/`dtpl-shimmer`）、一次性过冲
  反馈（`dtpl-refresh-pop`）与交错延迟（`12ms`/`.06s`）不在刻度内，写裸值是对的。
  悬停与当前项的底色同样只有两档：`--dtpl-wash-hover`（4%）与 `--dtpl-wash-on`（6%）。
  只收敛**取值等于这两档**的站点——3%/5%/7%~14% 各有其处（行悬停最轻、`bd-tab` 选中是 5%），
  不是同一个语义；承载读数的明度（`52/72/100` 那几档、柱高、相位段、轨道、占比环）**一律不碰**，
  它们与状态回洗在代码里长得一模一样（都是同一族 `color-mix` 百分比），只认站点不认数值。
- **读数面的层级也是刻度：受光边 `--dtpl-sheen`/`--dtpl-sheen-hover`、悬停抬升
  `--dtpl-lift`/`--dtpl-lift-hover`。** 卡片悬停不再各写一套 shadow 栈。
- **hero 图走 import，不走静态目录。** client 半区只有一个产物（`lib/client.js`），没有能挂相对 URL 的
  静态目录，所以 esbuild 把图内联成 data URI，由 `--dtpl-hero-art` 交给 CSS。拼那一行必须是普通字符串：
  换成模板字符串时，注入的整张样式表会被提前闭合，后面所有规则静默消失（实测底图声明只剩名字，
  计算值 `background-image: none`）。
- **图的高度是首屏预算算出来的，不是审美数字。** 140px 之上，趋势图就被挤出可视高度——「今日读数与
  近 14 天趋势一屏读完」是这张卡存在的理由。
- **骨架块与真块是一组数。** 骨架高度对上真块（hero 与四格同属一张卡，所以两块骨架之和要等于整卡高），
  数据到达时首屏才不整体下跳；改真块的高度或内边距必须同步改骨架。
- **直角是不变量，不是当前偏好。** 唯一允许的圆角是 0；真圆（状态点、表盘、轨道环、窄栏的圆形图标钮）
  写 50%。宿主的 `--dsw-corner-shape` 是超椭圆形状关键字、不是长度，喂进 `border-radius` 会让声明失效、
  圆角塌成 0——半径一律纯长度。
- **读数面是全窗口同一套配方：1px 硬边 + 3% 洗色 + 材质。** 材质是受光边加背光边两条，固定黑白、
  只走 1px、不超过 12%，叠在硬边之内——深色面上只有顶亮线读得出，浅色面上只有底暗线读得出，同一套
  材质两个主题各自成立。3% 洗色在深色下不另提亮，否则同屏会同时出现两种面板。一页里材质只给第一块
  读数面：第二块再上材质就与抬头抢。
- **设备皮是另一套账。** 独立悬浮窗口没有宿主，也就没有 `--dsw-alias-*` 可借：根上带
  `data-dtpl-device="light|dark"`，墨阶、黄与材质照旧，色值写死在 tokens 里那两段 `[data-dtpl-device]`；宿主里没人挂这个属性，
  所以那两块永远匹配不上。禁令对它同样成立——不直连 `--dsw-*`、不写字面色值、圆角只有 0。一处例外有
  实测理由：深皮的 err 换成亮一档的 `#ff6b61`，宿主那枚 `#f85149` 压屏面只有 4.45:1。

## 与其他面的关系（避免两个入口互相打架）

- 浮窗的**用量总览 / 用量明细**是**跨会话 · 按窗口**的视角；**词元**这一页是**单会话 · 全生命周期**的视角。
  第三种视角（**单项目 · 按窗口**）**还没有做**——那枚从侧栏项目行钻进去的入口见下一节。
- DSH 自己的会话级读数各有归属，本页**不重复**它们：整会话轮次数/步骤数/墙钟时间由 `sessionStats` 投影提供，
  四桶 token 由 `tokenUsage` 投影提供，上下文构成（system / tools / messages 的**估算**）由 `contextBreakdown` 投影提供并由 composer 的 ContextMeter 显示。
  本页的 token 与钱**只取账本**——同一批数字不设第二个来源（理由见 [`adr/0001-turn-attribution-read-time-join.md`](adr/0001-turn-attribution-read-time-join.md)）。

## 侧栏项目行入口（**尚未实现**）

> 这一节的词是为一个**还没落地的入口**定的：`src/` 里没有它的代码。写下它们是因为设计已定
> （[`adr/0002`](adr/0002-project-row-entry-via-dom-injection.md)），而改那一块之前得先有这套说法。

- **项目行（project row）** —— 侧栏按工作区分组时代表**一个已注册工作区**的那条分组行（折叠箭头 + 名称 + ⋯ + ⊕）。
  它**不是**一条会话行：会话行有宿主声明的扩展位，项目行没有（见
  [`adr/0002-project-row-entry-via-dom-injection.md`](adr/0002-project-row-entry-via-dom-injection.md)）。
- **项目身份** —— 项目行的身份就是工作区注册表的 `workspaceId`；它与账本侧 `WorkspaceUsageRow.id`
  **是同一个值**，所以「这行是哪个项目」不用另开一条数据通路。**未归属**分组没有这个身份
  （见 [`CONTRACTS.md`](CONTRACTS.md) §1），因此也不会有这枚入口。
- **注入点（injection point）** —— 这枚入口图标在宿主 DOM 里落地的坐标：项目行行尾那个操作容器里、
  ⋯ 之前。它**不是 slot**，一旦实现，那将是本插件唯一一处直接操作宿主 DOM 的地方。
