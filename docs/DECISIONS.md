### D-001 · 2026-09-06 · 以外部双半区 Cordis 插件形态发布

**Status: current** · supersedes: — · superseded-by: —

**决策。** 一个包、两个半区:host(`src/*.ts`)拥有全部数据,browser(`src/client/*.tsx`)只注册
slot(`sidebar.footer.action` + `shell.overlay`),两者经 feature-owned 精确 Fetch 路由通信。

**为什么不显然。** 前提是**不改 DSH 仓库**就扩展 `web` profile。DSH 的能力都是 Cordis 插件、
可带 client 半区,但**外部包**用不了单仓预设 `clientBundle()`,也贡献不了生成的 Typert Remote,
所以浏览器半区只能手写懒加载 CJS factory——而 **client 入口绝不能加 `default` 导出**:cordis
loader 的 `exports.default ?? exports` 会掩盖 `.inject`,插件以 "without inject" 坏掉。

**代价。** 半区边界与 wire 形状自己维护;换来装上即用的外置扩展。机制背景见 `docs/DESIGN.md` §3–§7。

### D-002 · 2026-09-06/07 · 逐请求账本行,而非每会话聚合

**Status: current** · supersedes: — · superseded-by: —

**决策。** **每次通道计费模型调用记一行** JSONL(以 message id 与合成 id 去重,失败尝试也只计数
写行),按**本地日历日**分区;首次启动与手动重扫靠重放 `sessionPersistence` 快照回填(幂等)。

**为什么不显然。** DSH 内置的每会话投影太粗——回答不了按天、按请求的问题,投影格式一变就得
重建;而「一次调用 = 一行」让去重、追加与跨重启的增量探测各自落在一条独立事实上。代价是自己
扛并发:追加走串行队列,跨模块级 HMR 重载的去重边界要显式定义(`docs/HMR.md` §4)。

**一个数据目录只允许一个写入进程**(`owner.json` 守卫):真正的风险在 rollup / 缓存 / 重折叠的
竞争,不在账本行本身。不变量见 `docs/CONTRACTS.md` §2 与 §3。

### D-003 · 2026-09-07/08 · 成本层 + 价格表;额度只从官方 API 取

**Status: partially superseded** · supersedes: — · superseded-by: D-004, D-011, D-014

云端合并计价与规则链由 D-011 作废,额度卡的三态前提由 D-014 取代;**额度只从官方 API 取**、
成本层与价格表仍生效。

**为什么不显然。** DSH 从不算钱,账本要回答「这花了多少」就必须自带价格表;而订阅额度是
**跨工具共享**的账户事实,本地账本无论如何算不出来——所以额度只拉各通道的官方账户端点,
绝不本地估算(估出来的数会随订阅到期静默变成谎话)。

**代价。** 记录只存**计价身份**、不存金额,价格在读取时解析,所以改价能重算历史、不必重建
账本;代价是价格表成为历史金额的唯一入口,删掉它历史只能读成「价格未知」(¥0)——口径是未知,
不是免费。规则见 `docs/CONTRACTS.md` §2,机制见 `src/pricing.ts`。

### D-012 · 2026-09-11 · 侧栏告急点只读持久化快照;client 按 surface 拆文件

**Status: partially superseded** · supersedes: — · superseded-by: D-014

额度卡「三态」的隐含前提由 D-014 取代;告急点只读快照与 client 按 surface 拆文件两条不变。

**告急点只读最近已知快照,绝不后台打官方 API。** 空闲时轮询通道账户端点会烧限流,不符合
单人工具的诚实最小面;所以色点由 host 从**持久化**的额度快照(任一窗口 ≥ 90% 或 `exceeded`)
推出,语义是「上次看时已经紧了」而不是实时配额。

**client 按 surface 拆文件(纯搬家,不改行为)**:浮窗只留外壳,总览 / 通道 / 口径各成文件,
共享格式化独立,**CSS 按固定顺序拼接**(级联顺序是契约)。同一把尺子也用在反面:`stats.ts`
越过 600 行线仍**不拆**——它的天然缝(纯折叠 ↔ 按日 IO + 缓存)只在真要动其中一半时才值得
切开。契约字段见 `docs/CONTRACTS.md`。

### D-013 · 2026-09-11 · 价段时间轴升级为两级:整点生效 + 每日时段(峰谷)

**Status: current** · supersedes: D-011 · superseded-by: —

取代 D-011「价段 = 四档价 + 生效日期」的时间轴部分(单手工表、路由卡、`$billing`、卡片并集不变)。

**为什么不显然。** 官方调价公告本身就发生在 12:00 这种**整点**上(维护者:「时间可以精准到
小时」),而峰谷不是另一段价,是**一段价内部**的第二层——DeepSeek 是「闲时价 + 工作日
9–12 / 14–18 高峰翻倍」。所以时间轴必须两级:先按记录时间戳取生效段,再在该段内按记录
**本地星期几 + 小时**取生效时段;时段带 `days`,否则周末会被按高峰价高估。

**两条取舍。** ① 取「全天价 + 峰谷时段」而不是「时段铺满 0–24」:空隙的含义天然唯一,写路径
不必去拦「有空隙」;② 时段身份 = `start` + `days` 而不是 `(start, end)`:改费率或结束小时能
就地重算那段历史,而改掉 `start`/`days` 或删掉时段会让身份悬空——那时必须报「价格未知」,
绝不静默按邻近时段计价。

**规则只写一遍**:「整点 / 星期几 / 时段冲突」放在一个纯模块里被 host 与 browser 共用,各写
一遍的代价是「草稿认为能存、写入被拒」。旧格式(纯日期)继续合法,要迁移的只有派生折叠。
界面规格见 `docs/DESIGN.md` §3.1,契约见 `docs/CONTRACTS.md` §2。

### D-014 · 2026-09-11 · 额度卡先判「什么在管这个账户」:订阅门 vs 余额门

**Status: current** · supersedes: D-003, D-012 · superseded-by: —

取代 D-003 / D-012 里「`ok` 卡一律按套餐窗口渲染」的隐含前提(官方端点、只读快照、告急点语义不变)。

**为什么不显然。** 套餐会过期,而旧行为两头都错:过期后端点仍回 200 → 仍判 `ok`,把「套餐
没了」画成「额度充裕」的绿卡;而余额字段拉了却从不显示,余额正是失效后唯一决定能不能继续
用的数字。

**决策。** `ok` 卡按门(`subscription` / `balance` / `none`)渲染;门是**读时派生**的纯函数、
不进快照,续费后不会被旧值掩盖。两条硬规则:

- **门只从「真的答复了」的端点推导,绝不从失败推导**:超时 / 5xx 是「不知道」而不是「没有
  订阅」,此时不设门(缺省 `subscription`);余额端点也没答复时不能把 `$0.00` 当真,降级为
  `none`。**门表达的是权益在不在,不是数据在不在。**
- **`403` 是一种状态,不是一次失败**:OpenCode Go 的 `403` = key 有效但没有 Go 订阅,落
  `ok` + `none`(401 仍是 `error`);Command Code 的未知状态词一律以是否在期(`periodEnd`)为准。

**代价。** 余额门要**换主体**而不是清空(对不再受约束的账户画窗口进度条就是伪造约束);
**明确不做**后台探测过期、用本地时钟推断套餐过期、给余额加告警阈值。官方原文与端点语义见
`docs/DESIGN.md` §3.1,规则见 `docs/CONTRACTS.md` §2。

### D-025 · 2026-09-13 · 视觉方向定为「明日方舟:终末地」:黑白灰基色、金属点缀、品牌黄作锚点

**Status: partially superseded** · supersedes: — · superseded-by: D-027

**决策:全窗口的视觉方向定为「明日方舟:终末地」那套语言**——黑白灰作基色、金属只作**点缀**、
品牌黄作锚点、直角硬边。界面**形态不跟随宿主**,只有颜色与主题跟随 DSH 皮肤(浅色 / 深色两套
皮肤下都成立)。

**理由。** 终末地不是经典方舟那套 HUD:配色围绕黄 / 黑 / 白,以亮白为主、气质克制,工业徽记在
各面板反复出现。选它的价值正在于它**不等于 DSH 自带的样子**——跟随宿主形状会让插件看起来仍是
宿主的一屏。

**黄是「料」,不是「线」。** `#FFCD00` 压在白卡上只有 1.57:1,拿它做分隔线、做浅底上的文字或
细柱都会糊掉;所以恒定只落在**实心块**上,且自带墨边或墨色内容(黄牌 + 黑字 / 黑边)。黄因此
有**预算**:只出现在「当前页 / 峰值 / 徽记」三处,其余一律中性。

### D-026 · 2026-09-13 · 用量总览改为「先给外面的人看」:一个窗口一句话、术语重写、清单按它编码的量排

**Status: current** · supersedes: — · superseded-by: —

**决策:界面上的每句话都按「第一次读到它的人」写。** 三条不变量:

- **一个窗口一句话。** 数字旁边写清它坐在哪个窗口里(「今日」/「累计」/「近 7 天」),口径写在
  句子里而不靠位置感;同一屏的节标题之间不许只差一个字——共用前缀只在真有父子关系时才算数。
- **术语重写。** 作者内化的词与插件的内部状态机对第一次用的人没有免疫:`用量未知` 改成
  `未上报用量`(「3 用量未知」语法上是断的),`输入` 改成 `未命中输入`(这一格是 prompt cache
  miss,不是「我发过去的全部文字」,误读代价最大)。**桶名与界面词继续一一对应**:`订阅价值`
  保留原名(曾改成「相当于省了」,判定更啰嗦,已撤回)。
- **清单顺序服从它编码的量。** 行按什么量排,就显示那个量、画那个量的占比条——按请求数降序却
  只显示词元,条长不单调,读起来像渲染坏了。

**理由。** 插件是要给别人用的,读者因此从写它的人变成第一次用它的本机用户:作者内化的词、内部
状态词、只有作者知道的排序约定都不再有免疫。代价是首屏偶尔多一行说明——那是**读懂**的代价,
不是功能的代价。界面词表随契约维护(`docs/CONTRACTS.md`),不在别处复述。

### D-027 · 2026-09-13 · 终末地语言铺满五个 tab:一块面板配方、唯一「当前项」、芯片四级、默认态不染色

**Status: partially superseded** · supersedes: D-025 · superseded-by: D-040

**「未保存」那一档**自 **D-040** 起降为 amber，且只在写不进去时出现（实心墨那一档现在只剩

**决策:把 D-025 的视觉方向铺满全部五个 tab**(此前只有外壳与用量总览做满)。四条规则:

- **一块面板配方**:所有读数面共用同一条边框(`--dtpl-border`)+ 同一个面板底色
  (`--dtpl-panel-bg`)+ 金属(`--dtpl-metal`);深色主题不再额外提亮——它会让通道卡 / 订阅卡比
  同屏 hero 更亮,一屏出现两种面板。

- **芯片是四级描边体系,不是色块矩阵**:默认描边 / 需看一眼(amber 边框)/ 未保存与「订阅」

  两枚不同层级的芯片会读成同一块灰。

  填充取 `--dtpl-fg-2`,只有 warn / danger 带色相。

**边界。** 品牌黄的预算**不扩大**(D-025 的三处);焦点环继续跟随 `--dtpl-accent`——焦点是系统
信号,不是这套视觉语言的一部分。

### D-030 · 2026-09-15 · 读路径不再 await 权威同步(后台自愈 + 15 s 节流)

**Status: current** · supersedes: — · superseded-by: —

**为什么不显然。** 慢的不是账本读,而是**每次读都先 await 一次权威 walk**(维护者:「tab 打开
怎么要加载半天」):新鲜度探针在当前会话上永远报 stale(每条消息都换一次 revision),而 walk 对该
会话**整份日志重读重折叠**——那些行**早已**由 `session/event` 实时 hook 记进账本了。

**决策。** 读路径只做廉价探针,需要折叠时把 walk **排到后台**,读立刻返回账本当前内容;后台
walk 按 **15 s** 节流;**没有基线签名的会话不受节流**(首次回填、刚开的新会话——便宜且该立刻
同步,这是自愈路径还活着的关键);唯一例外是**冷账本**(还没有任何日文件),那时等一轮,否则
首次安装会把「还没回填完」显示成「没有记录」。

**代价。** 账本可能比持久化日志晚至多一个节流窗口(15 s),滞后只落在「别的进程写下的行 /
折叠曾经失败」两种情况上;**重新扫描**仍立刻走全部会话。这几条不变量当时用一个慢的 persistence 桩验证过(那个桩随
2026-09-16 的自检精简一起删了,现在没有自动化守卫)。

### D-039 · 2026-09-17 · 价表行内四档价改为只读的「此刻价」,托底价是展开后的第一张

**Status: current** · supersedes: — · superseded-by: —

**决策。** 模型行右侧那四个数字**只读**,报的是**此刻计费所用的价**——生效段的全天价叠上此刻生效
的峰谷时段,与成本层取价同一条规则;改价一律点开这一行。展开后的**第一张固定是托底价**:没有生效
时刻、不能设时间也不能删,没被下面任一段调价覆盖的时间都按它算。整行(不只是行尾的 ▸)都是展开
热区,▸ 是它的键盘可达形态。调价段可以删(删掉 = 它覆盖的时间回到上一段或托底价),但**删除要点
两下**:它改的是那段历史的金额,而账本没有撤销,一次误点不值得换来重填四档价。

**为什么不显然。** 上一版行内可编辑,而它编辑的是「当前生效那一段的**全天价**」:读者看到四个数字
的第一反应是「这就是这个模型的价」,而它既不是此刻价(峰谷时段正在生效时更高),也不是只影响今天
的一个数(改它会把那一段的**全部历史**按新价重算)。同一个数字有三种读法,那就不是可发现性的问题,
是形状错了——**只读的此刻价 + 分开的「托底 / 调价史」两层**把「价是什么」与「怎么改」拆开。
托底价则把无起点段从「可以没有」变成「永远在」:每一行都至少有一张「其它时间按它算」的卡,
于是「价格未知」只剩两个触发(整行没价、或记录落在所有段之外),界面上不再有一个数字既像价又像待填项。

**代价。** 填一条新价从「行内一次按键」变成「展开 + 在托底卡里填」;wire 上撤掉 `now` / `nowFrom`
(行内价由 client 现算,存一份快照只会在改价后与历史分叉),preview 夹具随之不用再伪造它。
`anchoredRow`(把无起点段锚到首记整点的补丁)一并删除:无起点段不再是权宜状态,它就是托底价。
契约见 `docs/CONTRACTS.md` §2,形状见 `src/client/pricing/draft.ts` 与 `editors.tsx`。

### D-040 · 2026-09-17 · 价表自动保存只在提交点写与报,打字途中静默

**Status: current** · supersedes: D-027 · superseded-by: —

**决策。** 价格表仍然只有自动保存这一条写路径(不加保存按钮、不加快捷键),但**写与报都只在提交点**:
防抖到期(600 ms)尝试写——**草稿可写才写**,不可写(半输入的数字)时**保持沉默**,等这个字段失焦、
或下次回到面板,才把「未保存:〈地点〉的〈原因〉」报出来。字段失焦**立刻**写一次,不再等防抖。
「未保存」徽章只在**这次没能写进去**(草稿无效 / 宿主拒绝)时出现,因此它从实心墨降为 amber
——出现即「要看一眼」;正常在飞的瞬态由行左侧那道墨条(被动指示)承担。报出来的问题不因为继续打字
而撤回,只由**写成功**或**改动归零**清掉。

**为什么不显然。** 自动保存把「未保存」从一个**动作**(去按保存)变成一个**状态**(还没落盘),而这个
状态在打字途中是**必然**存在的:把 `1.5` 全选重打时中间一定是空值,而整文件校验在这一刻必然失败。
上一版在打字途中就报「未保存」,踩的是实测里最差的那一档——Etre / A List Apart 的 22 人实测中,
边打边报错、聚焦即报错的版本**更慢、错误更多、满意度更差**(「我还没开始它就红了」「你还没打完就
打红叉」),答完再报快了 7–10 s;GitLab 的 Saving 模式给的是同一条:**点击类改动立即存,打字类改动
在 blur 时存**,同时「最后一次按键后 3 秒」再兜一次。本地磁盘不会因此丢数据,但**报错时机**会教坏
人:一个还在被编辑的字段不是错误。

**代价。** 失焦立刻写把写入次数抬到「**每离开一个字段一次**」（连改四个单元格 = 数次整份文件写入），
所以**通知父级刷新被合进一个 1 s 的窗**：一次概览是全量聚合（实测 200–340 ms），连打时白跑四次不值；
离开面板时把还没发出的那次立刻补上（那一页自己不显示概览，所以这个窗看不见）。
多一个状态「已经交代过某个字段」(`committedRef`):一旦失焦过,此后每次失败都报,直到写成功——否则
一次被在飞写请求吞掉的报错会让提示永久消失,只剩一句「待保存…」。草稿无效时**永不落盘**是既有的
选择(半输入不能阻塞整表的其余部分),所以「未保存」仍可能长期挂着:它挂着的唯一原因只能是用户
自己留了一个坏字段。**不抛弃草稿**同样是既有的选择,理由在此补一遍:无效的中间态是打字的必经之路,
而写失败与用户的输入无关(磁盘只读 / 宿主拒绝 / 网络),丢弃等于静默撤销他刚做的编辑——而账本
没有撤销。看护这一链时记住它的隐含前提(draft 永不原地 mutate)见 `docs/LESSONS.md`。

### D-041 · 2026-09-18 · 价格表首屏:事实带 + 一条通道默认展开,折叠头自带读数

**Status: current** · supersedes: — · superseded-by: —

**决策。** 价格表 tab 的页头分成三样各管一件事的东西:**工具栏**(搜索 / 筛选 / 这次写没写进去)、
**事实带**(整张表的规模与缺口:`N 条通道 · M 个模型 · 其中 K 个价格未知(R 次请求按 ¥0 记)`)、
**图例**(一句话:四个数字是此刻计费所用的价、`—` 是什么意思)。**第一条通道默认展开**(host 正按
请求数排序,所以就是请求最多的那一条),其余收纳;收纳的卡头不再是挤成一行、用 `·` 串起来的长摘要,
而是**身份行 + 事实行**(模型数 / 请求数 / 其中几个价格未知)。图例从四行压到两行——「未保存」与
行左侧墨条的解释移交给它们各自已经在场的那处文案;工具栏状态文字在无事可报时**不再复述表的规模**。
读失败不再落到「没有可显示的路由」,而是与用量明细 / 额度同一形状的错误条 + 重试。

**为什么不显然。** 上一版的首屏是五条折叠头加一段四行说明书:读者到达这一页时**一个价都看不见**,
而他真正要回答的问题(这张价表有没有洞)在那段文字里也没有答案——「价格未知」只在展开之后才出现。
折叠本身是对的(账本可以有几十条通道),错的是**把折叠当成了默认的完整状态**:一个折叠头必须自己
说得出这条通道有没有问题,而「已定价 N 条模型」那类规模读数与「有没有洞」是两件事。`其中` 两个字
也不能省:它数的是「有账本记录落在价外」的模型,一条**已经写着价**的模型也可能在里面(写下的生效
时间静默截断了它之前的一切),所以它与总数之间不是「有价 / 无价」的划分——写成并列的类别会让读者
以为有一批模型压根没价。

**代价。** 首屏多一行(事实带 + 两行图例),折叠头从一行变两行(实测 34 → 63px):换来的是「不点
任何东西就知道这张表要不要管」。事实带里的请求数与模型数按**同一个 `priceUnknown` 判定**汇总,所以
补上托底价之后两者一起归零,屏幕上不会出现「0 个模型未知、却还有 N 次请求没价」这种自相矛盾的读数。
行内「价格未知」的文案补了第三种行(没有价、账本也从没调用过它):旧文案在那一行说「它的请求都按
¥0 记」是句假话,那些请求不存在。形状见 `src/client/pricing/PricingPanel.tsx` 与 `editors.tsx`,
「一串事实」的词汇与用量明细页头共用(`.dtpl-hero-facts`),推理见 `docs/DESIGN.md` §3.1。

## 如何追加条目

1. 在**文件末尾**追加 `### D-NNN · 日期 · 标题`。标题会被索引表逐字复用,所以写短语,不写句子。
2. **状态行照抄这个格式**(它与顶部索引表是人工对齐的,写错就对不上):

   ```
   **Status: current** · supersedes: — · superseded-by: —
   ```

   `supersedes` 列出**本条取代了谁**,`superseded-by` 列出**谁取代了本条**;多个 ID 用 `, `
   分隔,没有就写 `—`。取代关系必须**双向**:你写了 `superseded-by: D-027`,就要去 D-027 的
   `supersedes` 里写上本条。
3. **一条 ≤ 40 行**(`docs/WORKFLOW.md` §7):背景、决策、代价与取舍各一段,指向
   `docs/CONTRACTS.md`(契约)与 `docs/DESIGN.md`(更深的推理),而不是把它们抄一份。
4. 若是 `current` 或 `partially superseded`,在顶部索引表加一行——不进表就与正文不符;
   纯 `superseded` 的条目反倒**不能**进表。
5. 若新决策取代旧条目,**把旧条目的状态行一起改**(降级状态 + 双向链接)——与代码同一 commit。
